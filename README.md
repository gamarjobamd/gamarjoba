# Gamarjoba

Сайт грузинского ресторана «Gamarjoba», Кишинёв — [gamarjoba.md](https://gamarjoba.md).

Чистые HTML / CSS / JS. Ни фреймворков, ни зависимостей, ни шага сборки на сервере.

## Как это устроено

| Адрес | Файл |
|---|---|
| `/` | `index.html` |
| `/menu` | `menu.html` |
| `/dish/<slug>/` | `dish/<slug>/index.html` — генерируется |
| `/dish?item=<slug>` | `dish.html` — старые ссылки, перенаправляет на канонический адрес |
| 404 | `404.html` |

Cloudflare Pages отдаёт `menu.html` по адресу `/menu` сам: «чистые» адреса — его
поведение по умолчанию, настраивать нечего.

### Данные

Всё содержимое меню лежит в JS-файлах и больше нигде. Разметку никогда не правят руками.

| Файл | Что |
|---|---|
| `js/menu-data.js` | `MENU` — кухня, `BAR` — барная карта. Названия, граммовки, цены |
| `js/data.js` | `DISHES` — шесть фирменных блюд с развёрнутым описанием |
| `js/menu-full.js` | Полные описания из печатного меню, RO / RU / EN |
| `js/i18n.js` | Все строки интерфейса и переключатель языков |

Тексты трёхъязычные: `L(ru, ro, en)`. Выбранный язык хранится в `localStorage`.

### Шаблоны

`js/menu-template.js` и `js/dish-template.js` — чистые функции разметки: ни DOM,
ни браузерных API. Их использует и браузер, и генераторы. Второй копии шаблона
не существует, поэтому статика не может разойтись с тем, что видит посетитель.

## Сборка

Шага сборки у Cloudflare Pages нет: **результат генераторов коммитится в репозиторий**.
Оба скрипта запускаются вручную, каждый раз после правки данных меню.

```bash
node tools/build-menu.mjs      # пересобирает разделы внутри menu.html
node scripts/build-dishes.js   # страницы блюд, sitemap.xml и разметку Schema.org
```

У каждого есть режим проверки — он ничего не пишет и падает с кодом 1,
если собранное разошлось с тем, что лежит в репозитории:

```bash
node tools/build-menu.mjs --check && node scripts/build-dishes.js --check
```

Прогоняйте проверку перед коммитом. Если она падает — запустите генераторы
и закоммитьте результат вместе с правкой данных.

### Что делает `scripts/build-dishes.js`

Раньше `/dish?item=<slug>` отдавал пустой HTML: заголовок «Блюдо — Gamarjoba»
и `<main>`, который заполнял скрипт. Краулеры и мессенджеры видели пустышку.

Теперь у каждого блюда своя статическая страница `dish/<slug>/index.html` —
с собственным `<title>`, `description`, `canonical`, полным набором Open Graph
и фотографией, и с содержимым прямо в разметке. Каркас берётся из `dish.html`,
разметка — из `js/dish-template.js`, данные — из файлов выше.

Каталог `dish/` пересобирается целиком: страницы удалённых блюд не переживают
сборку и не остаются в индексе. Заодно переписываются `sitemap.xml` и разметка
Schema.org — `Restaurant` на главной и `Menu` на `/menu`, обе из тех же данных,
чтобы цены в разметке не разъезжались с ценами в меню.

### Тексты на вычитку

```bash
node scripts/export-translations.js
```

Собирает `content/translations-template.csv` — все 539 строк сайта
(интерфейс, названия и описания блюд) в колонках `key, ru, ro, en`.
Файл нужен, чтобы отдать тексты носителю языка; правки возвращаются
руками в JS-файлы с данными, источник остаётся там. Флаг `--blank`
очищает колонки `ro` и `en`.

План языковых версий — в `content/i18n-plan.md`.

## Локальный просмотр

```bash
node tools/serve.mjs
```

Открывает `http://localhost:4173`. Обычный статический сервер отдаёт 404 на `/menu`
и `/dish` — этот повторяет порядок разрешения адресов Cloudflare Pages
(файл → `<путь>.html` → `<путь>/index.html` → `404.html`).

## Заказы

Корзина живёт в `localStorage`. «Заказать в WhatsApp» собирает состав заказа,
имя, телефон и комментарий в текст сообщения и открывает его в WhatsApp
ресторана (+373 69 904 304). Заказ приходит обычным сообщением — нигде,
кроме переписки, он не сохраняется.

## Деплой

Cloudflare Pages, репозиторий `gamarjobamd/gamarjoba`, ветка `main`,
output directory `/`. Пуш в `main` публикует сайт.

При правке CSS или JS поднимайте номер в `?v=` у ссылок на них во всех HTML —
иначе у вернувшихся посетителей останется старая версия из кеша.

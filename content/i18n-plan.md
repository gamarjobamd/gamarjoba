# Языковые версии: предложение

Документ — план, а не реализация. Ничего из описанного здесь на сайте пока нет.

## Что уже есть, а чего нет

В шапке заявлены RO / RU / EN, и переключатель настоящий: он меняет и интерфейс,
и названия блюд, и описания, и `<title>` с `description`, и `<html lang>`.

Чего нет — **отдельных адресов**. Все три языка живут по одному URL, выбор
хранится в `localStorage` и применяется скриптом уже после загрузки страницы.
Для гостя это работает. Для поисковика — нет: краулер приходит без
`localStorage`, всегда получает русскую версию и индексирует только её.

Практически это значит, что по запросу «restaurant georgian Chișinău» сайт
не находится вообще: румынского текста в индексе не существует. Для Кишинёва
это самый заметный пробел на всём сайте.

Важно: **тексты переводить не нужно.** Румынский и английский уже написаны
и лежат в репозитории — все 539 строк, ни одного пробела. Задача не в переводе,
а в том, чтобы дать каждому языку собственный адрес.

## Предлагаемая структура

```
/            RU   (остаётся как есть, ничего не переезжает)
/ro/         RO
/en/         EN
```

Плюс `/ro/menu`, `/en/menu`, `/ro/dish/<slug>/`, `/en/dish/<slug>/` — то же
дерево, что и сейчас, с языковым префиксом.

### Почему папки, а не переключение скриптом

1. **Индексируется только то, у чего есть адрес.** Поисковику нужен URL,
   который отдаёт румынский текст в HTML. Скрипт, меняющий тексты после
   загрузки, такого адреса не создаёт: страница одна, и в индекс попадает
   один язык из трёх.
2. **Ссылку нельзя переслать.** Сейчас гость выбирает EN, копирует адрес,
   отправляет другу — тот открывает по-русски, потому что язык лежит
   в `localStorage` отправителя, а не в ссылке.
3. **Превью в мессенджерах.** WhatsApp и Telegram не выполняют скрипты:
   заголовок и описание в карточке ссылки всегда будут русскими,
   какой бы язык ни выбрал отправитель.
4. **`hreflang` физически некуда поставить.** Он связывает разные URL.
   При одном адресе на три языка эта разметка невозможна.
5. **Стоимость нулевая.** Генераторы уже собирают статику из данных
   и уже параметризованы языком: `tools/build-menu.mjs` и
   `scripts/build-dishes.js` принимают `LANG` и просто зашиты на `"ru"`.
   Три прохода вместо одного дают три дерева страниц. Тексты, шаблоны
   и вёрстка — те же самые, второй копии не появляется.

Альтернатива — отдавать язык по заголовку `Accept-Language` с одного адреса —
для Cloudflare Pages означает функцию на границе и один URL на три языка,
то есть ту же проблему с индексацией. Не стоит усложнения.

### Что переключатель языков должен делать после этого

Не перезагружать текущую страницу, а вести на неё же в другой версии:
`/menu` → `/ro/menu`, `/dish/adjaruli/` → `/en/dish/adjaruli/`.
Выбор по-прежнему можно помнить в `localStorage`, но адрес становится главным.

## Блок hreflang

Ставится в `<head>` **каждой** страницы всех трёх версий, одинаковым набором,
включая ссылку на саму себя — так требует спецификация. Ниже — для главной:

```html
<link rel="alternate" hreflang="ru" href="https://gamarjoba.md/" />
<link rel="alternate" hreflang="ro" href="https://gamarjoba.md/ro/" />
<link rel="alternate" hreflang="en" href="https://gamarjoba.md/en/" />
<link rel="alternate" hreflang="x-default" href="https://gamarjoba.md/" />
```

Для меню:

```html
<link rel="alternate" hreflang="ru" href="https://gamarjoba.md/menu" />
<link rel="alternate" hreflang="ro" href="https://gamarjoba.md/ro/menu" />
<link rel="alternate" hreflang="en" href="https://gamarjoba.md/en/menu" />
<link rel="alternate" hreflang="x-default" href="https://gamarjoba.md/menu" />
```

Для страницы блюда (на примере `adjaruli`):

```html
<link rel="alternate" hreflang="ru" href="https://gamarjoba.md/dish/adjaruli/" />
<link rel="alternate" hreflang="ro" href="https://gamarjoba.md/ro/dish/adjaruli/" />
<link rel="alternate" hreflang="en" href="https://gamarjoba.md/en/dish/adjaruli/" />
<link rel="alternate" hreflang="x-default" href="https://gamarjoba.md/dish/adjaruli/" />
```

`x-default` указывает на русскую версию: она остаётся версией по умолчанию
для всех, чей язык не совпал ни с одним из трёх.

Вместе с `hreflang` на каждой странице должны поменяться:
`canonical` — на собственный адрес версии (у румынской страницы канонический
адрес румынский, а не русский), `og:locale` — на `ro_RO` / `en_US`,
`<html lang>` — уже проставляется скриптом, но в статике должен стоять сразу.
И `sitemap.xml` вырастает втрое: 70 адресов → 210.

## Объём

| | Строк |
|---|---|
| Всего строк в `translations-template.csv` | 539 |
| Из них язык-независимых (Shurpa, Borjomi, Pepsi — одинаково во всех трёх) | 109 |
| Реально переводимых | 430 |
| **Не переведено на румынский или английский** | **0** |

Объём русского текста — 19 691 знак, около 11 стандартных страниц.

Перевод не требуется. Требуется **вычитка** носителем: тексты писались
не в бюро переводов, и перед сдачей румынскую версию стоит показать человеку,
для которого румынский родной. Отдельного внимания заслуживают названия
грузинских блюд — их лучше не переводить вовсе, а оставить транслитерацию,
как сделано сейчас.

## Порядок работ

1. Вычитка `content/translations-template.csv` носителем румынского.
   Английский — по остаточному принципу, он нужен туристам, а не поиску.
2. Правки из CSV вносятся обратно в `js/i18n.js`, `js/menu-data.js`,
   `js/menu-full.js`, `js/data.js` — источник данных остаётся там,
   CSV нужен только как удобная форма для вычитки.
3. Генераторы прогоняются по трём языкам, появляются `/ro/` и `/en/`.
4. На всех страницах — `hreflang`, свой `canonical`, свой `og:locale`.
5. Переключатель языков переводится с перезагрузки на переход по адресу.
6. `sitemap.xml` пересобирается на три версии.
